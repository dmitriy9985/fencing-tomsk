# Настройка админки новостей

Админка находится по адресу `/admin/`. Она управляет только новостями и не требует от тренера доступа к GitHub.

## 1. Создайте проект Supabase

1. Откройте [supabase.com](https://supabase.com/) и войдите в аккаунт.
2. Нажмите **New project**.
3. Укажите название проекта, надёжный пароль базы данных и ближайший доступный регион.
4. Дождитесь окончания создания проекта.

Пароль базы данных не нужно добавлять в файлы сайта.

## 2. Выполните `setup.sql`

1. В Supabase откройте **SQL Editor**.
2. Нажмите **New query**.
3. Откройте в проекте файл `supabase/setup.sql` и скопируйте его целиком.
4. Вставьте SQL в редактор Supabase.
5. Нажмите **Run**.

Скрипт создаст:

- таблицу `news`;
- таблицу разрешённых администраторов `admin_users`;
- правила RLS;
- хранилище `news-images`;
- правила загрузки и удаления фотографий;
- три новости, которые уже есть на сайте.

Повторный запуск не должен дублировать три первоначальные новости.

## 3. Проверьте хранилище фотографий

После выполнения SQL:

1. Откройте раздел **Storage**.
2. Убедитесь, что появился bucket `news-images`.
3. Он должен быть публичным только для просмотра фотографий.
4. Загрузка и удаление файлов защищены RLS и разрешены только администратору.

Создавать bucket вручную обычно не требуется. Если он не появился, проверьте сообщения об ошибках в SQL Editor и повторите выполнение `setup.sql`.

## 4. Создайте администратора

1. Откройте **Authentication → Users**.
2. Нажмите **Add user**.
3. Укажите email тренера и надёжный пароль.
4. Если доступен переключатель подтверждения, создайте пользователя с подтверждённым email (**Auto Confirm User**).
5. Не включайте публичную регистрацию пользователей. В настройках Email provider отключите возможность самостоятельной регистрации, если она включена.

После создания пользователя вернитесь в **SQL Editor** и выполните, заменив адрес на реальный email:

```sql
insert into public.admin_users (user_id)
select id
from auth.users
where email = 'trainer@example.com'
on conflict (user_id) do nothing;
```

Авторизованный пользователь, которого нет в `admin_users`, не сможет читать черновики или изменять новости.

## 5. Найдите Project URL и публичный ключ

В Supabase откройте **Project Settings → API** или окно **Connect**.

Нужны только:

- **Project URL** — адрес вида `https://abcdefgh.supabase.co`;
- **Publishable key** — ключ вида `sb_publishable_...`.

Если проект показывает старые ключи, вместо Publishable key можно использовать **anon public key**.

Никогда не копируйте в сайт:

- `secret key`;
- `service_role key`;
- пароль базы данных;
- пароль администратора.

## 6. Вставьте два публичных значения

Откройте файл `js/supabase-config.js`:

```js
window.SUPABASE_CONFIG = Object.freeze({
  url: "YOUR_SUPABASE_URL",
  anonKey: "YOUR_SUPABASE_ANON_KEY"
});
```

Замените:

- `YOUR_SUPABASE_URL` на Project URL;
- `YOUR_SUPABASE_ANON_KEY` на Publishable key или anon public key.

Другие файлы для подключения редактировать не нужно.

## 7. Проверьте сайт локально

Не открывайте HTML двойным щелчком. Запустите локальный веб-сервер из корня проекта:

```bash
python3 -m http.server 8000
```

Затем откройте:

- основной сайт: `http://localhost:8000/`;
- админку: `http://localhost:8000/admin/`.

Остановить сервер можно сочетанием `Ctrl+C` в терминале.

## 8. Проверьте вход

1. Откройте `/admin/`.
2. Введите email и пароль созданного пользователя.
3. После входа должен появиться список из трёх первоначальных новостей.
4. Выйдите и попробуйте неверный пароль — список и редактор не должны открыться.

## 9. Проверьте добавление новости

1. Нажмите **+ Добавить новость**.
2. Заполните заголовок, дату, краткое описание и полный текст.
3. Выберите фотографию JPG, JPEG, PNG или WEBP.
4. Включите **Опубликовано**.
5. Проверьте карточку в блоке **Предпросмотр**.
6. Нажмите **Сохранить**.
7. Обновите основной сайт. Новость должна появиться первой, если у неё самая новая дата.

## 10. Проверьте черновик и изменение

1. Создайте ещё одну новость без флажка **Опубликовано**.
2. Она должна появиться в админке со статусом **Черновик**, но не на основном сайте.
3. Нажмите **Изменить**, исправьте текст и включите публикацию.
4. После сохранения новость должна появиться на основном сайте.

## 11. Проверьте фотографию

1. Загрузите фотографию размером до 10 МБ.
2. После сохранения откройте **Storage → news-images** и убедитесь, что файл появился.
3. Замените фотографию у этой новости.
4. Новая фотография должна появиться, а старый файл должен быть удалён.

Bucket принимает файл не более 5 МБ. Админка автоматически уменьшает большие изображения до максимальной стороны 1920 px. Если файл после уменьшения всё равно больше 5 МБ, будет показана ошибка.

## 12. Проверьте удаление

1. Нажмите **Удалить** у тестовой новости.
2. Админка должна запросить подтверждение.
3. После подтверждения новость должна исчезнуть из списка и с основного сайта.
4. Загруженная для неё фотография должна исчезнуть из `news-images`.

Первоначальные изображения находятся в GitHub-репозитории, поэтому удаление первоначальной записи не удаляет обычный файл из папки `images`.

## 13. Проверьте защиту от постороннего пользователя

1. Убедитесь, что самостоятельная регистрация в Supabase выключена.
2. Откройте сайт в приватном окне браузера — должны отображаться только опубликованные новости.
3. Откройте `/admin/` — без входа редактор и список новостей недоступны.
4. Если хотите проверить второго пользователя, создайте его в Authentication, но **не добавляйте** в `admin_users`. Вход для него будет отклонён сообщением об отсутствии доступа администратора.
5. В Supabase откройте **Table Editor → news** и убедитесь, что у таблицы включён RLS.
6. В **Storage → Policies** убедитесь, что загрузка и удаление `news-images` разрешены только роли `authenticated` с проверкой записи в `admin_users`.

## Публикация

После локальной проверки изменения можно закоммитить в отдельной ветке и опубликовать через обычный процесс GitHub Pages. Объединять ветку с `main` следует только после проверки админки с реальным Supabase-проектом.
