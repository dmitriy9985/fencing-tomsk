# Добавление соревнований в календарь

В списке соревнований откройте карточку или её постоянный адрес. Кнопка «Добавить в календарь» раскрывает три ссылки. Apple получает HTTP-адрес отдельного события, Google открывает форму с названием, адресом, датами и описанием, а «Скачать .ics» сохраняет файл из браузера. Форма Google выставляет технический интервал в один час, если время старта известно, а время окончания отсутствует. В описании есть напоминание проверить длительность. В .ics для такого однодневного события есть только время начала. Для многодневного события обе версии включают последний календарный день. При неизвестном времени создаётся событие на весь день.

Apple документирует импорт .ics из приложения «Почта» и отдельную подписку на календарь. На физическом iPhone Safari открыл системный экран импорта из локального предпросмотра. Владелец подтвердил добавление события на 19–20 декабря 2026 года. На рабочем HTTPS-адресе этот сценарий нужно повторить после развёртывания. Если Safari скачал файл, попробуйте открыть его из загрузок. Если в просмотре нет действия «Добавить», отправьте .ics себе по почте и откройте вложение именно в приложении «Почта». [Инструкция Apple](https://support.apple.com/guide/iphone/set-up-mail-contacts-and-calendar-accounts-ipha0d932e96/ios)

## Проверка на iPhone перед выпуском

1. Подключите Mac и iPhone к одной частной сети Wi-Fi. В Finder откройте рабочую папку ветки `work/calendar-export-links` и дважды нажмите [Start-Calendar-Preview.command](../Start-Calendar-Preview.command). Нужен установленный Deno. Терминал проверит порт 8787, определит локальный IPv4 и проверит HTTP-ответы карточки и файла .ics.
2. Оставьте окно Терминала открытым. На iPhone в Safari откройте **полный адрес из этого окна**, включая `http://`. Пример: `http://192.168.1.10:8787/calendar/event/?id=11`. После смены Wi-Fi перезапустите файл и используйте новый адрес. Адрес `127.0.0.1` предназначен только для проверки на Mac.
3. Нажмите «Добавить в календарь», затем «Apple Календарь». Отметьте, что открылось: окно импорта, предварительный просмотр, загрузка файла или другой экран. Если Safari скачал файл, нажмите значок загрузок и откройте `ffto-event-11.ics`.
4. Если доступно действие «Добавить» или «Добавить все», выберите тестовый календарь и проверьте результат в приложении «Календарь». Событие «[Тест] Юный мушкетёр» должно занимать **19 и 20 декабря 2026 года, весь день**. 21 декабря в событие не входит.
5. Сообщите версию iOS, какой экран показал Safari и на каком шаге удалось добавить событие. После проверки удалите тестовое событие и нажмите **Control+C** в окне Терминала.

### Если iPhone не подключается

- Если Терминал сообщает, что порт занят, остановите предыдущий предпросмотр в его окне и откройте файл повторно. Запуск не завершает процессы, уже слушающие порт.
- Откройте выведенный адрес на самом Mac. Если он работает, проверьте, что на iPhone выбрана та же Wi-Fi-сеть и что это не гостевая сеть, в которой устройства изолированы. Если macOS запрашивает доступ Терминала к локальной сети, разрешите его для этого запуска. При включённом VPN убедитесь, что доступ к локальной сети разрешён, и при необходимости повторите тест без VPN.
- Если сеть всё равно блокирует подключение, на Mac скачайте .ics с тестовой карточки и отправьте его себе как вложение. На iPhone откройте вложение именно в приложении «Почта». Это проверяет импорт в Apple Календарь. Переход из Safari проверяется отдельно в частной сети, где устройства видят друг друга.

Этот предпросмотр использует тот же обработчик .ics, что и Edge Function. Тестовые события хранятся в памяти локального сервера. Веб-страницы и Edge Function на рабочем сайте читают опубликованные события из Supabase.

## Развёртывание после согласования

1. Сверьте актуальный `main`, коммит PR №33 и успешные проверки GitHub. Зафиксируйте коммит `main` до выпуска и выполните сборку из согласованного коммита. Миграций, загрузки тестовых турниров и изменений ключей не требуется.
2. Разверните только Edge Function `calendar-event-ics` в проекте `fencing-tomsk`. Для перехода из Safari входная проверка JWT отключается у этой функции. Запрос к Data API использует серверный `SUPABASE_ANON_KEY`, существующие RLS и условие `published=true`. Функция дополнительно проверяет возвращённые ID и признак публикации.
3. Чтобы упаковка не зависела от доступа Supabase к исходникам за пределами каталога функции, соберите отдельный временный каталог. После согласования команды выполняются из корня проверенного checkout. Подставьте подтверждённый идентификатор рабочего проекта вместо `PROJECT_REF`.

   ```sh
   stage="$(mktemp -d)"
   mkdir -p "$stage/supabase/functions/calendar-event-ics"
   deno bundle --no-config --no-lock --no-remote --check --platform deno \
     supabase/functions/calendar-event-ics/index.ts \
     -o "$stage/supabase/functions/calendar-event-ics/bundle.mjs"
   printf '%s\n' 'import "./bundle.mjs";' > "$stage/supabase/functions/calendar-event-ics/index.ts"
   deno check --no-config --no-lock --no-remote "$stage/supabase/functions/calendar-event-ics/index.ts"
   cd "$stage"
   supabase init
   supabase functions deploy calendar-event-ics --remote=PROJECT_REF --use-api --no-verify-jwt
   ```

4. До слияния PR проверьте HTTPS-адрес `https://PROJECT_REF.supabase.co/functions/v1/calendar-event-ics/11.ics` без ключа и токена. GET и HEAD должны вернуть 200, `Content-Type: text/calendar; charset=utf-8` и `Content-Disposition: inline`. Проверьте, что файл содержит рабочее название, ссылку на карточку ФФТО и 19–20 декабря включительно. Для существующего черновика, отсутствующего ID и записи без точной даты ожидается 404, для POST — 405. Повторите импорт через Safari на физическом iPhone с этого HTTPS-адреса. Если проверка не прошла, оставьте сайт на прежнем интерфейсе с выгрузкой .ics.
5. После этих проверок объедините PR, дождитесь GitHub Pages и проверьте все три действия в модальном окне и на постоянной карточке. При проблеме после выпуска верните изменения PR отдельным revert-коммитом и дождитесь повторного развёртывания Pages. Если проблема касается доступа к данным, сразу отключите или удалите только `calendar-event-ics`. [Настройка Edge Functions](https://supabase.com/docs/guides/functions/function-configuration) · [Команды Supabase CLI](https://supabase.com/docs/reference/cli/supabase-functions-deploy)

## Возможная подписка

Для отдельной подписки нужен постоянный HTTPS-адрес одного iCalendar-фида с опубликованными событиями, стабильными UID и датами обновлений. Apple позволяет подписаться на такой фид как на отдельный календарь только для чтения. Частоту получения изменений определяет клиент. Функция подписки потребует отдельного согласования. [Подписки Apple Календаря](https://support.apple.com/en-us/102301)
