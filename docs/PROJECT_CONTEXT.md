## Архитектура и исходники

Сайт состоит из статических HTML, CSS и браузерного JavaScript. Сборочного фреймворка нет. Тексты и ряд фотографий находятся в репозитории, динамические разделы читают опубликованные данные Supabase. Браузер использует публичный ключ, административные операции защищены авторизацией и правилами базы.

| Участок | Исходники и назначение |
| --- | --- |
| Главная и общий интерфейс | `index.html`, `styles.css`, `js/site.js`. Навигация, главная и адаптивное оформление |
| Новости, календарь, результаты и галерея | `news/`, `calendar/`, `results/`, `gallery/`. Список и карточка новости в `js/news-page.js`, структурированные результаты в `js/results-page.js`, данные главной, календаря и галереи в `js/site-content.js` |
| Запись, площадки, тренеры и контакты | `start/`, `organizations/`, `coaches/`, `contacts/`. Площадки и руководство находятся в «Организациях», подробные профили в «Тренерах» |
| Экипировка и пожертвования | `equipment/`, `support/`, `js/donation.js`. Памятка, QR и реквизиты. Буфер обмена работает в браузере, сам перевод выполняется через банк |
| Расписание | `training/`, `js/training-schedule.js`, `admin/training.js`. Регулярные слоты и исключения хранятся отдельно |
| Административная панель | `admin/index.html`, `admin/admin.js`, `admin/shared.js` и модули разделов. Используются Supabase Auth и `admin_users` |
| Схема данных | SQL в `supabase/` описывает миграции. Фактически применённую схему и права сверяют отдельно |

## Решения, которые важно сохранить

- Окончательно утверждённый оригинал эмблемы ФФТО хранится в `images/logo/ffto-emblem-tgpu.png`. На страницах используются WebP 144, 480 и 640 px с версией в URL. Эмблема в блоке «О федерации» занимает 312 px на широком экране. Значок iOS подготовлен отдельно в 180 px. Значки вкладки используются в размерах 16 и 32 px (`logoffto-16.png` и `logoffto.png`).
- Календарь отбирает актуальные опубликованные события по времени Томска до применения лимита. Событие с диапазоном видно до конца последнего дня. При сбое показывается состояние ошибки. Календарь и результаты остаются отдельными разделами.
- Регулярное расписание относится к залу «Акватика» на Ленина, 207. Временное исключение затрагивает одно занятие. Администратор подтверждает отмену, перенос или возврат к обычному расписанию один раз. Публичная страница читает сохранённое состояние, сервер проверяет право на запись.
- MAX отправляет уведомления через транзакционную очередь и Edge Function. Cron служит резервом. Наблюдение за реальными отправками и состояние очереди на дату сверки описаны в [журнале](PROJECT_JOURNAL.md#уведомления-max-о-тренировках).
- Результаты разделены на запись соревнования и дочерние строки участников в `competition_result_entries`. Сохраняются личные, командные и прочие результаты, включая возможность двух третьих мест. Место проведения не определяет регион спортсмена. Редактор сохраняет итог, участников и статус публикации одним вызовом `save_competition_result`. Связи, протокол, состав и опубликованный статус остаются в существующей модели.
- Сохраняйте используемые схемы и связи для `news`, `competition_events` и результатов. В новости `published=false` означает черновик. После возобновления автоматизации выпуск черновика остаётся ручным действием уполномоченного администратора.
- Текущий сайт и рабочие данные меняются только в согласованном объёме. Публичные проверки чтения не подтверждают права на запись. Изолируйте проверки записи и держите закрытые данные и секреты вне исходников.

## Календарь (выпуск 3.3)

В админке по умолчанию открываются актуальные соревнования, включая черновики. Прошедшие и все события доступны через фильтр периода. Отдельно можно выбрать статус публикации. Даты сравниваются по Томску. В списке видны даты, название, категория и короткое место. Подробности открываются в модальном окне и по постоянному адресу. Для длинной программы используйте описание подробной карточки, а правила допуска и документы размещайте по официальным ссылкам. [Поведение, оптимизация изображений и аудит MAX](RELEASE_3_3.md).

## Карточки соревнований (выпуск 3.2)

Постоянный адрес турнира — `/calendar/event/?id=N`, где N — идентификатор `competition_events`. Он сохраняется после изменения названия, дат и завершения турнира. В админке у опубликованного события ссылка «Карточка». Снятие с публикации закрывает карточку. Проверки черновиков и записи выполняют в изолированной среде.

В календаре редактор указывает категорию турнира, а возраст и допуск участников — в описании. В поле места можно указать город, зал и адрес. Сбор и начало относятся к первому дню. Для времени указывают часовой пояс места проведения, например `Asia/Tomsk`. Для положения достаточно публичной HTTPS-ссылки на документ организатора. Для второго документа заполняют название и ссылку. Контакт предназначен для публикации. Привязка результата к событию и новости выполняется в редакторе результатов по существующим идентификаторам.

`supabase/calendar-event-details.sql` однократно расширяет существующую таблицу до публикации сайта. Новые поля необязательны. Файл календаря создаёт `js/event-calendar.js`. При точной дате без времени файл включает весь диапазон по последний день. При наличии времени он содержит начало или, когда известно только оно, время сбора. Для многодневного события без часа окончания включён весь последний календарный день. Проверка формата — `node --test tests/event-calendar.test.cjs`.

### Индивидуальные превью новостей

GitHub Pages отдаёт общий HTML для всех `/news/?id=N`. Публикация из админки изменяет Supabase независимо от Pages. Для индивидуальных Open Graph-превью нужен отдельный этап: генерировать HTML для путей `/news/N/` из опубликованных записей, безопасно запускать пересборку при публикации, изменении и снятии новости и удалять устаревшие страницы. Сохранить старые ссылки, проверить исходный HTML, затем фактическое превью в мессенджере с учётом его кеша. Приватный ключ GitHub в браузерную админку не помещать.
